# HackAlem AI — локальное автопротоколирование совещаний

Система принимает запись совещания, готовит русско-казахскую транскрибацию,
разделяет реплики спикеров, формирует саммари и поручения, а затем экспортирует
протокол. Целевой режим — закрытый контур: аудио, транскрипты и модели не
передаются во внешние API.

## Текущий статус

Завершены этапы 1–3 и техническая часть этапа 4: подготовлена локальная
инфраструктура, обработка аудио, распознавание смешанной казахско-русской речи
и воспроизводимое сравнение двух локальных ASR-моделей. Ручная оценка точности
на эталонной разметке остаётся открытой.
Python-сервис сообщает состояние устройства, FFmpeg и каталоги моделей,
принимает MP3/WAV/M4A/MP4, нормализует их в WAV 16 kHz mono и выделяет речевые
фрагменты с временными метками. Диаризация, локальная LLM и пользовательский
интерфейс будут добавляться последовательно.

```text
Next.js интерфейс
        ↓  localhost only
Next.js API `/api/asr/health`
        ↓  localhost only
Python FastAPI `services/asr`
        ↓
проверка файла → FFmpeg → VAD → фрагменты речи
        ↓
локальный rukk ASR → очередь → транскрипт
        ↓
диаризация → локальная LLM → DOCX/PDF
```

## Требования

- macOS на Apple Silicon;
- Node.js 20+;
- Python 3.13.13;
- Python 3.12 — только для необязательного сравнения NVIDIA NeMo;
- FFmpeg 9+.

Установите FFmpeg через Homebrew, если команды `ffmpeg -version` ещё нет:

```bash
brew install ffmpeg
```

## Первый запуск

Установите зависимости Next.js:

```bash
npm install
cp .env.example .env.local
```

Создайте окружение локального сервиса:

```bash
cd services/asr
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
set -a; source .env; set +a
make download-rukk
```

`make download-rukk` скачивает ровно два публичных файла в
`services/asr/models/asr/rukk/`: TorchScript-веса и список токенов. Это
разовая загрузка около 721 MB; после неё распознавание выполняется без сети.

Запустите оба процесса в двух терминалах из корня репозитория:

```bash
npm run dev:asr
```

```bash
npm run dev
```

Проверки:

```bash
curl http://127.0.0.1:8000/health
curl http://127.0.0.1:3000/api/asr/health
```

Оба запроса должны вернуть `status: "ok"`. Если ASR-сервис ещё не запущен,
второй запрос вернёт понятную локальную ошибку и не выполнит внешний запрос.

## Конфигурация

- [`services/asr/.env.example`](./services/asr/.env.example) задаёт пути к
  локальным моделям, `ASR_DEVICE` (`auto`, `mps`, `cpu`) и путь к FFmpeg.
- [`.env.example`](./.env.example) задаёт только локальный адрес ASR-сервиса.
  Адреса, не указывающие на localhost, блокируются API-прокси.
- Веса моделей и временные файлы исключены из Git.

## Что уже доступно

### Проверка инфраструктуры

`GET /health` возвращает статус сервиса, фактически выбранное устройство,
доступность FFmpeg и состояние трёх локальных каталогов моделей.

### Подготовка записи

`POST /prepare-audio` принимает `multipart/form-data` с полем `file`.
Допустимы MP3, WAV, M4A и MP4. Сервис ограничивает размер (1 GiB по умолчанию)
и длительность (4 часа), приводит аудио к `16 kHz / mono / PCM 16-bit`,
нормализует громкость и выполняет локальный энергетический VAD. Длинные
участки тишины исключаются, речь нарезается на фрагменты до 18 секунд с
перекрытием 1 секунду.

```bash
curl -X POST http://127.0.0.1:8000/prepare-audio \
  -F 'file=@/полный/путь/к/совещанию.mp3;type=audio/mpeg'
```

В ответе остаются только метаданные: длительность, формат и временные метки
фрагментов. Исходный файл, WAV и фрагменты удаляются до завершения запроса.

Тестовые записи из `ТЗ` уже прошли этот этап локально:

| Запись | Длительность | Речевых фрагментов |
| --- | ---: | ---: |
| `Совещание №1.mp3` | 274,25 с | 30 |
| `Совещание №2.mp3` | 206,03 с | 24 |

### Локальная транскрибация

Основная модель — [`alibiserikbay/kazakh-russian-mixed-stt`](https://huggingface.co/alibiserikbay/kazakh-russian-mixed-stt), вариант `asr/rukk`. Это TorchScript-модель CTC для казахской, русской и смешанной речи; используются только `model.pt` и `tokens.lst`, без языковых моделей. Лицензия весов — Apache-2.0.

После старта сервиса модель загружается один раз. `ASR_DEVICE=auto` выбирает MPS, если он доступен в PyTorch, а при ошибке MPS повторяет работу на CPU. Фактически выбранное устройство отображается в `/health`.

```bash
curl -X POST http://127.0.0.1:8000/transcribe \
  -F 'file=@/полный/путь/к/совещанию.mp3;type=audio/mpeg'
```

Ответ: `{"id":"…","status":"queued"}`. Затем:

```bash
curl http://127.0.0.1:8000/jobs/<id>
curl http://127.0.0.1:8000/jobs/<id>/result
curl -X DELETE http://127.0.0.1:8000/jobs/<id>
```

Очередь исполняет одно задание одновременно. Результат содержит общий текст и
сегменты `{ id, start_seconds, end_seconds, text }`; повтор в границах
перекрывающихся фрагментов удаляется. Аудиофайлы удаляются сразу по окончании
задания, а текст хранится в памяти до `DELETE /jobs/<id>` или перезапуска
сервиса.

### Проверка альтернативной ASR-модели

Основной моделью MVP выбрана `rukk`: на обеих записях из `ТЗ` она быстрее
NVIDIA NeMo и не требует отдельного тяжёлого окружения. Адаптер NeMo оставлен
как локальный инструмент сравнения; он не подключён к HTTP-маршруту и не может
отправить запись во внешний сервис.

```bash
cd services/asr
make install-nemo
make download-nemo
source .venv/bin/activate
make benchmark-rukk RECORDING='/полный/путь/к/совещанию.mp3'
make benchmark-nemo RECORDING='/полный/путь/к/совещанию.mp3'
```

NeMo запускается в `.venv-nemo` на Python 3.12: его зависимость `kaldialign`
сейчас несовместима с Python 3.13. Вес модели занимает около 459 MB и имеет
лицензию CC-BY-4.0. Подробная методика, команды и результаты двух измерений
приведены в [README сервиса](./services/asr/README.md#сравнение-asr-моделей).
Сравнение показывает скорость, память и полноту сегментов; для вывода о
точности имён, дат и смешанной речи необходима ручная проверка с эталоном.

Следующим компонентом выбрана локальная диаризация
`pyannote/speaker-diarization-community-1` (CC-BY-4.0). Её веса gated: прежде
чем продолжить интеграцию, владелец проекта должен сам принять условия модели
в Hugging Face и скачать её в локальное хранилище. Токен не будет сохраняться
в репозитории или передаваться сервису.

## Приватность и ограничения

Аудио не хранится после завершения задания. Веса моделей не скачиваются во
время обработки. Логи Next.js и FastAPI содержат только идентификатор задания,
статус, длительность и число фрагментов — без аудио, транскриптов, имён файлов
или их частей. Требование закрытого контура будет сохранено при добавлении
следующих этапов.
