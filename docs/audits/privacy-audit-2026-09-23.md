# Аудит приватности локального контура

Дата: 23 сентября 2026 года.

## Вывод

В штатном сценарии после предварительной загрузки весов запись, транскрипт,
протокол и экспорт не покидают компьютер. Веб-интерфейс, FastAPI и Ollama
привязаны к loopback-адресам; внешние AI-маршруты отключены. Аудит закрыл
обнаруженный риск освобождённых страниц SQLite: при удалении задания хранилище
включает `secure_delete` и уплотняет базу.

Это проверка исходного кода, конфигурации и локальных слушателей, а не
криминалистическая гарантия отсутствия данных в резервных копиях, snapshots или
на носителе после удаления.

## Проверенные потоки данных

| Поток | Защита | Результат |
| --- | --- | --- |
| Браузер → Next.js | `127.0.0.1:3000` | локально |
| Next.js → ASR | `lib/local-asr.ts` принимает только `127.0.0.1`, `localhost` или `::1` | локально |
| ASR → Ollama | `Settings._local_runtime_url` разрешает только HTTP loopback без учётных данных | локально |
| Аудио → FFmpeg, VAD, ASR, pyannote | дочерние процессы и локальные файлы рабочего каталога | локально |
| Внешние AI API | `/api/ai` и `/api/analyze` возвращают `410`; SDK аналитики в исходном коде не найдены | заблокировано |

Локальная проверка слушателей в день аудита показала только `127.0.0.1:3000`,
`127.0.0.1:8000` и `127.0.0.1:11434`. Это подтверждает границы запущенных
сервисов, но не заменяет пакетный захват на уровне ОС.

## Данные и журналы

- Файл проходит проверку расширения, MIME-типа, размера до 1 GiB и длительности
  до 4 часов в `services/asr/app/audio.py`.
- Временные исходник, WAV и фрагменты удаляются в `finally` после обработки.
- SQLite хранит только завершённый транскрипт и протокол в
  `services/asr/runtime/protocols.sqlite3`; аудио в неё не записывается. Каталог
  runtime исключён из Git.
- `DELETE /jobs/{id}` удаляет снимок и рабочую папку. `LocalProtocolStore`
  использует `PRAGMA secure_delete = ON` и `VACUUM` после успешного удаления,
  чтобы не оставлять текст в свободных страницах базы.
- FastAPI журналирует случайный ID, этап, процент, длительность и число
  фрагментов. Next.js журналирует ID запроса, маршрут, статус, длительность и
  исход. Содержимое аудио, имя файла, транскрипт и протокол в эти записи не
  передаются.
- Экспорт DOCX/PDF создаётся в памяти и передаётся браузеру. После скачивания
  ответственность за файл лежит на пользователе и настройках браузера.

## Границы и остаточные риски

- База SQLite не зашифрована. Локальный пользователь с доступом к учётной записи
  или диску может прочитать незакрытые задания. Для более строгой модели нужен
  зашифрованный диск и отдельная учётная запись.
- `secure_delete` не управляет Time Machine, облачными синхронизациями,
  snapshots файловой системы и уже существующими копиями данных.
- Первичная загрузка rukk, pyannote и Ollama-модели обращается к их поставщикам
  по явной команде пользователя. Это отдельный подготовительный шаг, а не
  обработка совещания. Токен Hugging Face вводится интерактивно и не хранится в
  `.env` или репозитории.
- `NEXT_TELEMETRY_DISABLED=1` добавлен в команды frontend, чтобы фреймворк не
  отправлял телеметрию во время локальной разработки и сборки.
- В `ТЗ/` и в `services/asr/runtime/` находятся локальные исходные материалы и
  результаты; оба пути исключены из Git. Подробный отчёт сравнения хранится
  только в runtime, а версия в `docs/quality/` содержит лишь агрегаты.

## Воспроизводимая проверка

1. Запустить frontend, ASR и Ollama только на `127.0.0.1`.
2. В новой сессии выполнить `npm run lint`, `npm run typecheck`, backend-тесты
   и сравнение из раздела «Проверка качества» в README.
3. Удалить тестовое задание через интерфейс или `DELETE /jobs/<id>`; затем
   убедиться, что результат недоступен по API.
4. Перед демонстрацией отключить сеть и обработать заранее подготовленную
   запись. Первичная загрузка весов должна быть завершена до этого шага.
