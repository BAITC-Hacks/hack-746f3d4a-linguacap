# Локальный ASR-сервис

FastAPI-сервис для локального конвейера распознавания, диаризации и анализа
совещаний. Он не содержит API-ключей и не отправляет аудио, транскрипты или
модельные запросы во внешние сервисы.

## Требования

- macOS на Apple Silicon;
- Python `3.13.13` (см. `.python-version`);
- FFmpeg, доступный как `ffmpeg` в `PATH`;
- Node.js-приложение запускается отдельно из корня репозитория.

Для macOS с Homebrew:

```bash
brew install ffmpeg
```

## Запуск

```bash
cd services/asr
python3 -m venv .venv
source .venv/bin/activate
make install
cp .env.example .env
set -a; source .env; set +a
make dev
```

Проверка в отдельном терминале:

```bash
curl http://127.0.0.1:8000/health
```

В ответе отображаются выбранное устройство, доступность FFmpeg/FFprobe,
Python-зависимостей и конкретных файлов моделей. `status: "ok"` означает, что
сервис запущен; `ready.transcription`, `ready.diarization` и `ready.analysis`
показывают доступность отдельных этапов. Для Ollama проверяются запущенный
локальный сервис и точное имя установленной модели. Интерфейс показывает
недостающие компоненты и команды установки. Системные пакеты и gated-модели
устанавливаются вручную; после установки перезапустите ASR-сервис.

## Подготовка аудио

`POST /prepare-audio` принимает один MP3, WAV, M4A или MP4, проверяет его тип,
размер и длительность, затем локально выполняет:

1. FFmpeg-конвертацию в 16-bit WAV, 16 kHz, mono с нормализацией громкости.
2. Энергетический VAD без сетевых вызовов и выделение речевых интервалов.
3. Нарезку речи на фрагменты не длиннее 18 секунд с перекрытием 1 секунду.
4. Возврат только метаданных фрагментов и временных меток.

Все исходные, нормализованные и нарезанные файлы удаляются до завершения
запроса. Этот маршрут служит для проверки этапа подготовки; в следующем этапе
`POST /transcribe` будет хранить фрагменты лишь на время локального задания
распознавания.

```bash
curl -X POST http://127.0.0.1:8000/prepare-audio \
  -F 'file=@/полный/путь/к/совещанию.mp3;type=audio/mpeg'
```

Ответ содержит длительность источника и список `{ id, start_seconds,
end_seconds }`. Содержимое аудио в ответ и логи не попадает.

## Конфигурация

Все переменные перечислены в `.env.example`. Пути к моделям по умолчанию
находятся в `services/asr/models/` и не попадают в Git. `ASR_DEVICE` принимает
только `auto`, `mps` или `cpu`. При `auto` сервис использует MPS, если PyTorch
подтверждает доступность Metal; при недоступности или ошибке выбирается CPU.

Для подготовки аудио предусмотрены безопасные значения по умолчанию:

| Переменная | Значение | Назначение |
| --- | ---: | --- |
| `ASR_MAX_UPLOAD_BYTES` | 1 GiB | максимальный размер исходного файла |
| `ASR_MAX_AUDIO_DURATION_SECONDS` | 14 400 | максимальная длительность, 4 часа |
| `ASR_CHUNK_DURATION_SECONDS` | 18 | максимальная длина речевого фрагмента |
| `ASR_CHUNK_OVERLAP_SECONDS` | 1 | перекрытие соседних длинных фрагментов |
| `ASR_RUNTIME_DIR` | `runtime` | временные локальные файлы, исключённые из Git |

## Локальная транскрибация

Сервис использует вариант `asr/rukk` модели
[`alibiserikbay/kazakh-russian-mixed-stt`](https://huggingface.co/alibiserikbay/kazakh-russian-mixed-stt).
После активации `.venv` скачайте только необходимые веса:

```bash
make download-rukk
```

Команда сохраняет `model.pt` и `tokens.lst` в `models/asr/rukk/`; эти 721 MB
не добавляются в Git. Модель загружается один раз при старте сервиса и работает
только с подготовленными WAV-фрагментами. Используется greedy CTC-декодирование;
языковые модели KenLM намеренно не скачиваются на этом этапе.

```bash
curl -X POST http://127.0.0.1:8000/transcribe \
  -F 'file=@/полный/путь/к/совещанию.mp3;type=audio/mpeg'
curl http://127.0.0.1:8000/jobs/<id>
curl http://127.0.0.1:8000/jobs/<id>/result
curl -X DELETE http://127.0.0.1:8000/jobs/<id>
```

### Прогресс и локальный журнал

`GET /jobs/<id>` возвращает реальный этап, процент и компактный список событий:
ожидание в очереди, подготовка аудио, диаризация, распознавание фрагментов и
завершение. Процент распознавания обновляется по мере обработки фрагментов, а
не по таймеру. В терминале ASR-сервиса те же структурированные записи имеют
префиксы `asr_job_` и `asr_protocol_`.

Ни интерфейс, ни терминальный журнал не записывают имя файла, аудио, текст
транскрипта или сгенерированное саммари. Это журнал технических этапов текущего
локального задания; список событий не сохраняется после перезапуска сервиса.

В очереди выполняется только одно задание: это ограничение защищает 16 GB RAM.
`DELETE` немедленно удаляет завершённое задание и его текст; для активного
задания оно запрашивает отмену и очистит файлы после остановки worker’а.

### Локальное сохранение и правки результата

После успешной обработки сервис сохраняет транскрипт и, если он уже создан,
протокол в локальную SQLite-базу `ASR_PROTOCOL_STORE_PATH`. По умолчанию это
`runtime/protocols.sqlite3`; файл не добавляется в Git. Поэтому завершённый
результат, переименования спикеров и отредактированные поручения доступны после
перезапуска ASR-сервиса. Исходное аудио, нормализованный WAV и фрагменты в базу
не попадают и удаляются после обработки.

Изменить текст одной реплики можно локально:

```bash
curl -X PUT http://127.0.0.1:8000/jobs/<id>/segments/chunk-0001 \
  -H 'Content-Type: application/json' \
  -d '{"text":"Исправленный текст реплики"}'
```

После изменения транскрипта прежние саммари и поручения намеренно удаляются:
их нужно сформировать заново, чтобы источники оставались достоверными. В
интерфейсе можно редактировать описание поручения, ответственного и срок. Он
выделяет предупреждение, если ответственный или срок не заполнены. `DELETE
/jobs/<id>` удаляет также сохранённый локальный снимок.

### Экспорт протокола

Когда для расшифровки уже сформированы саммари и поручения, сервис создаёт
DOCX или PDF по образцу структуры протоколов из каталога `ТЗ`: тема, дата
формирования, участники, расшифровка, саммари, ключевые вопросы и таблица
поручений. Экспорт всегда использует текущие сохранённые пользовательские
правки. Он формируется в памяти и возвращается как скачиваемый ответ, поэтому
отдельный файл не сохраняется в `runtime`.

```bash
curl -OJ http://127.0.0.1:8000/jobs/<id>/export/docx
curl -OJ http://127.0.0.1:8000/jobs/<id>/export/pdf
```

PDF встраивает локальный системный шрифт с поддержкой кириллицы и казахских
символов. DOCX использует стандартную разметку Word с повторяемой шапкой
таблицы поручений и открывается без обращения к облачному сервису.

## Сравнение ASR-моделей

Основная модель MVP — `rukk`: на двух записях проекта она быстрее альтернативы
и запускается в основном окружении Python 3.13. Вторая модель —
[`nvidia/stt_kk_ru_fastconformer_hybrid_large`](https://huggingface.co/nvidia/stt_kk_ru_fastconformer_hybrid_large)
(лицензия CC-BY-4.0) — подключена отдельным локальным адаптером NeMo для
контрольных сравнений. Её архив весов занимает около 459 MB.

NeMo 2.7.3 не устанавливается в Python 3.13 из-за зависимости `kaldialign`,
поэтому сравнение воспроизводится в изолированном Python 3.12-окружении и не
меняет рабочий сервис:

```bash
cd services/asr
make install-nemo
make download-nemo
source .venv/bin/activate
make benchmark-rukk RECORDING='/полный/путь/к/совещанию.mp3'
make benchmark-nemo RECORDING='/полный/путь/к/совещанию.mp3'
```

Команды используют одинаковую подготовку аудио и VAD-фрагменты, не выводят
текст расшифровки и удаляют временные WAV-файлы. Результат содержит длительность
записи, число фрагментов, `transcription_seconds`, стандартный
`realtime_factor` (меньше — лучше), `speed_x_realtime` (больше — лучше) и
пиковый RSS процесса.

Измерения от 23 сентября 2026 года на CPU в изолированных окружениях:

| Запись | Модель | Фрагменты | Время | Скорость | Пиковая память |
| --- | --- | ---: | ---: | ---: | ---: |
| `Совещание №1` (274,25 с) | rukk | 30 | 9,59 с | 28,6× realtime | 1 712 MB |
| `Совещание №1` (274,25 с) | NeMo | 30 | 12,89 с | 21,3× realtime | 1 535 MB |
| `Совещание №2` (206,03 с) | rukk | 24 | 9,02 с | 22,8× realtime | 1 744 MB |
| `Совещание №2` (206,03 с) | NeMo | 24 | 12,09 с | 17,0× realtime | 1 533 MB |

Обе модели вернули непустой результат для каждого речевого фрагмента. Эти
записи не содержат размеченного эталонного текста, поэтому таблица **не**
доказывает точность имён, дат, чисел или русско-казахского переключения. Перед
заменой основной модели нужно вручную оценить обе расшифровки по этим критериям
на согласованном наборе с эталонной разметкой.

## Локальная диаризация

Для этапа 5 выбран `pyannote/speaker-diarization-community-1`: он возвращает
временные интервалы спикеров и может работать из заранее скачанной локальной
папки; лицензия весов — CC-BY-4.0. Runtime ставится в уже используемое
Python 3.12-окружение:

```bash
cd services/asr
make install-nemo
make install-diarization
# владелец сам вводит токен в интерактивной утилите; токен не попадёт в проект
.venv-nemo/bin/hf auth login
make download-pyannote
```

Модель gated: владелец проекта должен один раз принять её условия на странице
модели. Затем `hf auth login` интерактивно запрашивает личный Hugging Face
токен, а `make download-pyannote` копирует все файлы пайплайна в
`models/diarization/pyannote-community-1/`. Токен не добавляется в `.env`, не
передаётся API и не нужен во время диаризации. До появления локальных весов
сервис продолжает выполнять ASR, а диаризация остаётся выключенной. Адаптер передаёт в pyannote уже
нормализованный `16 kHz / mono / PCM 16-bit` WAV как локальный массив памяти,
поэтому не зависит от декодирования через TorchCodec и не требует менять
установленный FFmpeg 9.

После установки запускайте сервис в окружении с pyannote:

```bash
cd ../..
npm run dev:asr:full
```

После установки весов `POST /transcribe` дополнит каждый сегмент полями
`speaker_id` и `speaker_name`, а результат — списком `speakers`. Начальные
имена нейтральны (`Спикер 1`, `Спикер 2`); переименовать участника для всех
его сегментов можно локально:

```bash
curl -X POST http://127.0.0.1:8000/jobs/<id>/speakers/SPEAKER_01 \
  -H 'Content-Type: application/json' \
  -d '{"display_name":"Ерлан"}'
```

Проверка от 23 сентября 2026 года: веса `pyannote` (около 32 MB) загружены в
локальную папку, а короткий фрагмент из `Совещание №1` успешно прошёл весь
локальный маршрут `POST /transcribe`. Результат включал один сегмент с
`SPEAKER_01` и нейтральным именем. Smoke-проверка подтверждает установку,
контракт API и привязку временных меток, но не заменяет ручную оценку качества
на записи с двумя и более спикерами.

## Локальный анализ транскрипта

Этап 6 подготовлен так, чтобы текст совещания не мог уйти на внешний адрес.
По умолчанию `ASR_LOCAL_LLM_PROVIDER=disabled`, и маршрут анализа ответит
`503`, не передавая транскрипт куда-либо. Единственный предусмотренный runtime
— Ollama, причём `ASR_LOCAL_LLM_BASE_URL` принимает только `http`-адрес на
`127.0.0.1`, `localhost` или `::1`; адреса с учётными данными, query-параметрами
и внешними хостами отклоняются при старте.

В качестве базовой модели проекта установлен `qwen3:4b` (около 2,5 GB).
Первичная загрузка выполяется один раз и требует интернет; последующий анализ
работает офлайн. Ollama должен слушать только loopback-интерфейс:

```bash
brew install ollama
OLLAMA_HOST=127.0.0.1:11434 ollama serve
ollama pull qwen3:4b
```

Затем задайте в `.env` точное имя модели и перезапустите ASR-сервис:

```bash
ASR_LOCAL_LLM_PROVIDER=ollama
ASR_LOCAL_LLM_BASE_URL=http://127.0.0.1:11434
ASR_LOCAL_LLM_MODEL=qwen3:4b
# Стандартный каталог Ollama; измените, если задан OLLAMA_MODELS.
ASR_LLM_MODEL_DIR=~/.ollama/models
```

Затем для завершённой расшифровки доступен локальный запрос:

```bash
curl -X POST http://127.0.0.1:8000/jobs/<id>/analysis
curl http://127.0.0.1:8000/jobs/<id>/analysis
```

Анализатор передаёт модели только сегменты текущего задания и требует один
строгий JSON-объект: `title`, `summary`, `key_points` и `action_items`.
У поручения обязательны `description`, `source_segment_ids`, `confidence` в
диапазоне от 0 до 1 и `status: "new"`. Идентификаторы источников сверяются с
фактическими сегментами транскрипта; незнакомая ссылка, невалидная дата или
другой формат ответа отклоняются и не сохраняются. `assignee` и `deadline`
остаются `null`, если модель не может подтвердить их по исходной реплике;
относительный срок, например «до пятницы», хранится только в `deadline_text`.

Модель выбрана как отправная точка, а не как подтверждённый эталон качества для
русско-казахских совещаний. Перед рабочим использованием нужно вручную оценить
не менее 20–30 реальных фрагментов, особенно имена, даты, сроки и смешанную
русско-казахскую речь.

## Ограничение приватности

Сервис не содержит API-ключей, внешних сетевых клиентов или фоновой загрузки
моделей. При включённом анализе допускается только локальное соединение с
Ollama на loopback-адресе. Все будущие модели должны быть заранее скачаны в
локальные каталоги. Первичная загрузка `rukk`, необязательных весов NeMo и
явно выбранной локальной LLM — единственные команды, которым нужен интернет;
обработка записей выполняется офлайн.
